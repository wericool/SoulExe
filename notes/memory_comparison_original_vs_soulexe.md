# Память: оригинальный Soul of Waifu и SoulExe

## Короткий вывод

Оба приложения **не обязаны удалять сохранённую историю чата**, чтобы удерживать запрос в контексте модели. Оба хранят полную переписку и используют краткую долговременную память, а в сам запрос отправляют только свежую часть истории, которая помещается в контекст.

Главная практическая разница была не в самой идее памяти, а в **расписании тяжёлых служебных запросов**. В старой версии SoulExe Full Soul Memory и Summary могли запускаться сразу после ответа друг за другом. На локальном llama.cpp с одним слотом это занимало модель на десятки секунд. Новый SoulExe переносит тяжёлую работу на реальную паузу пользователя и отменяет ожидающую работу при следующем сообщении.

## Оригинальный Soul of Waifu

### История и контекст

Оригинал хранит всю историю чата, `summary_text` и номер последнего сообщения, вошедшего в сводку. Перед ответом он собирает системные блоки, карточку персонажа, лор, персону пользователя, Summary и данные Soul Memory. После этого он отбирает историю **с последней реплики к первой**, пока она входит в доступный бюджет.

Для оценки оригинал применяет `tiktoken` с кодировкой `cl100k_base` и оставляет резерв в 500 токенов под новый ответ. Если свободного места остаётся слишком мало, он отправляет только системный контекст и текущее сообщение. Старые сообщения не удаляются из файла чата: они лишь временно не попадают в конкретный запрос.

### Summary

После ответа оригинал создаёт фоновую задачу Auto-Summary. Она обрабатывает один хронологический блок новых реплик и делает **один запрос к модели**, затем записывает новую сводку и номер последней обработанной реплики.

### Soul Memory

В оригинале Soul Memory тоже запускается в фоне после ответа. Она работает пачками; стандартный размер пачки в коде — четыре новые реплики. В полном режиме она может вызывать Router, Archivist для тем и дневник. То есть **полная память оригинала также не обязательно состоит из одного запроса**. Router определяет важные факты, темы и изменения отношений; Archivist обновляет тематические файлы; Diary создаёт личную запись персонажа.

Auto-Summary и Soul Memory в оригинале создаются отдельными асинхронными задачами сразу после ответа. Это сохраняет отзывчивость Qt-интерфейса, но не гарантирует свободный слот локальной модели. Если локальный сервер имеет один слот, следующий запрос может ждать, пока завершатся фоновые задачи. При удалённом провайдере эта проблема обычно заметна меньше.

## SoulExe до оптимизации

SoulExe также хранил всю историю, Summary, индекс памяти, профиль пользователя, темы и дневник. В режиме Full его пайплайн выполнял Router, затем тематические обновления и дневник, после чего мог сразу запуститься Summary. Это полезно для насыщенной долгой ролевой игры, но при `--parallel 1` превращало модель в занятую очередь.

В пользовательском журнале одна такая последовательность заняла около 26 секунд: три запроса Soul Memory примерно на 8,0, 4,4 и 5,7 секунды, затем Summary примерно на 8,4 секунды. Поэтому после уже готового ответа создавалось впечатление зависания или ожидания следующей реплики.

## SoulExe после оптимизации

Новая версия не выключает память и не стирает историю. Она меняет приоритеты.

| Правило | Поведение новой версии |
|---|---|
| Запуск фоновой работы | Старый режим «сразу в фоне» на первом старте новой версии переводится в «после паузы» с ожиданием 60 секунд. |
| Новое сообщение пользователя | Отменяет ожидающее фоновое обслуживание. |
| Когда одновременно нужны Summary и Full Memory | Сначала выполняется одна короткая Summary; подробная память переносится на следующую настоящую паузу. |
| Служебные ответы модели | Ограничены 960 токенами и более низкой температурой. |
| Долгая история | Сохраняется полностью, но старая часть временно не передаётся модели при нехватке контекста. |

## Что будет потеряно при упрощении до одной Summary

Если оставить только Auto-Summary и отключить Soul Memory, исчезнут отдельные структурированные сведения о персонаже и пользователе, тематические глубокие заметки и личный дневник. Для большинства коротких и средних чатов одной Summary достаточно; для длинной ролевой истории память заметно помогает удерживать отношения, обещания, изменения состояния и повторяющиеся темы.

Если выбрать **Index only + Summary**, сохраняются краткий профиль персонажа, пользовательские факты и динамика отношений, но отключаются темы и дневник. Это наиболее быстрый компромисс для локальной модели с одним слотом.

Полное копирование оригинальной Full Soul Memory не решит проблему задержек само по себе: оригинальный полный режим тоже может делать несколько фоновых запросов. Полезнее оставить возможности SoulExe, но запускать их реже и только в момент реального простоя — именно это делает новая версия.

## Рекомендации

| Приоритет | Настройка |
|---|---|
| Максимальная скорость и простота | Summary включена, Soul Memory выключена. |
| Хорошая память без заметных задержек | Summary + `Index only`, интервал 10–12 реплик, пауза 60 секунд. |
| Максимально глубокая ролевая память | Summary + `Full`, интервал 10–15 реплик, пауза 60–120 секунд. |

Даже в режиме Full интерфейс не должен зависать после ответа: тяжёлая работа теперь ожидает паузу, а новое сообщение отменяет ожидающую задачу.
