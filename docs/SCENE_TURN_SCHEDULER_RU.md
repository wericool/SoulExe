# Единый планировщик автоматических сцен

В ветке `testing` автоматический ход сцены выполняет `SceneTurnScheduler`. Его единственный источник времени — сохранённое поле `SoulScene.NextTurnAt`; оно уже передаётся клиентам в LAN API и остаётся частью старой JSON-модели сцены.

| Ответственность | Компонент | Правило |
|---|---|---|
| Вычислить и сохранить время следующего хода | `SceneService.SetStatusAsync` / `ConversationTurnPolicy` | Пишет `NextTurnAt` только для `running` + `alternate` + задержки от 5 секунд. |
| Дождаться срока и вызвать генерацию | `SceneTurnScheduler` | На каждую сцену существует не более одного активного цикла; повторное планирование отменяет предыдущий. |
| Защитить генерацию от гонок | `ConversationTurnRunner` | Параллельная попытка получает `AlreadyRunning`, не добавляя дубль сообщения. |
| Показать отсчёт в Windows | `MainViewModel.ScheduleSceneTimer` | Только визуальный UI-отсчёт; он больше не запускает генерацию. |
| Команды старых LAN-клиентов `start`, `pause`, `next` | `ControlSceneFromNetworkAsync` | Сохраняют прежние маршруты, но отменяют/планируют только через единый scheduler. |

> Автоматические сцены не переносятся в новую JSON-схему на этом этапе. При перезапуске приложения сохранённый `NextTurnAt` остаётся каноническим состоянием, однако запуск восстановления всех просроченных задач пока является отдельным будущим решением. Это намеренное ограничение: оно предотвращает неожиданную генерацию после перезапуска до появления явной политики восстановления.

Пауза, завершение, удаление сцены, ручной выбор следующего участника и ошибка лимита контекста отменяют планировщик. Ручная генерация перед началом также отменяет прежнее ожидание, а после успешно сохранённого автоматического хода новый `NextTurnAt` получает новый единый цикл.
