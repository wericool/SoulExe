# LAN API Conversation — совместимый read-контракт

Этот документ описывает **добавочный** API ветки `testing`. Он представляет текущие `SoulChat` и `SoulScene` как единый разговор, но **не создаёт новую JSON-коллекцию** и не переписывает пользовательские данные. Существующие маршруты `/api/chat`, `/api/scenes` и `/api/characters/.../chats` остаются рабочими для ранее выпущенных Mobile-клиентов.

| Маршрут | Назначение | История в ответе |
|---|---|---|
| `GET /api/conversations` | Совместимый массив разговоров, отсортированный по обновлению | Вся история по умолчанию; `?take=1..100` оставляет последние сообщения каждого разговора. |
| `GET /api/conversations/{id}` | Один разговор по сохранённому `SoulChat.Id` или `SoulScene.Id` | Вся история по умолчанию; `?take=1..100` оставляет последние сообщения. |
| `GET /api/conversations/page` | Новая страничная выборка для будущих клиентов | `?limit=1..100`, `?take=1..100`, опциональный непрозрачный `cursor`. По умолчанию — до 50 разговоров с полной историей. |

Ответ страницы имеет форму `{ items, nextCursor }`. Клиент должен передавать `nextCursor` как есть и не пытаться интерпретировать его содержимое. При отсутствии следующей страницы `nextCursor` равен `null`.

## Единая модель ответа

| Поле | Значение |
|---|---|
| `kind` | `direct` для обычного чата или `scene` для сцены. |
| `participants` | Пользователь, персонажи и при необходимости режиссёр; персонажу передаются `characterId` и безопасный относительный `avatarUrl`. |
| `messages` | Хронологический список с `message`, `director` или `system`; вложения не раскрывают локальные файловые пути. |
| `context` | Контекст разговора: сценарий, место, время, настроение, цель и отношения, когда они существуют. |
| `turnState` | Только для сцен: статус, режим, следующий участник, время следующего хода и правила автоматического развития. |

`avatarUrl` является LAN-маршрутом `/api/characters/{id}/avatar?...`; Mobile-клиент добавляет короткоживущую сессионную строку запроса, потому что компонент изображения не передаёт заголовок авторизации. Файловый путь аватара с ПК в API не передаётся.

## Границы текущего этапа

Контракт пока **read-only**. Отправка обычных реплик, действия сцены и режиссёрские события продолжают выполняться через legacy-маршруты. Это преднамеренно: общий сервис мутаций и единый планировщик ходов должны пройти отдельные проверки до включения новых write-endpoint.

> Наличие `/api/conversations` не означает, что данные уже мигрированы в новую структуру. Источником остаются прежние `Characters[].Chats` и `Scenes`; `ConversationReadService` лишь строит безопасную проекцию для чтения.

Перед переключением списка Mobile на этот маршрут следует запрашивать `GET /api/conversations/page?limit=50&take=1`. Так список получает участников, статус, последнюю реплику и аватары без передачи полной истории каждой переписки.
