# Подготовка миграции Conversation: dry-run и резервная копия

В ветке `testing` реализован только **подготовительный** этап будущей миграции Conversation. `ConversationMigrationPreflight` строит текущую общую read-проекцию на копии `SoulDataRoot` и проверяет её инварианты. Он не выполняет запись в `soulexe.json`, не создаёт коллекцию `Conversations` и не повышает `SchemaVersion` выше **8**.

| Проверка dry-run | Причина |
|---|---|
| Число разговоров равно сумме всех `Characters[].Chats` и `Scenes`. | Не допускает тихой потери диалога при проекции. |
| Идентификаторы разговоров уникальны. | Сохраняет способность однозначно открыть существующую историю. |
| Обычный чат имеет пользователя и персонажа; сцена — двух персонажей и режиссёра. | Сохраняет семантику участников. |
| Номера реплик не повторяются, а содержимое не пустое. | Защищает порядок истории и обнаруживает повреждённые данные до миграции. |

`ConversationMigrationPreparationService.CreateVerifiedBackupAsync()` сначала выполняет dry-run, а затем создаёт резервную копию через существующий `JsonDataStore` с меткой `conversation_schema_v9_preflight`. Эта операция **не вызывается автоматически** ни при запуске, ни при чтении данных.

> Реальная schema v9 будет допустима только после отдельного round-trip теста: legacy JSON → candidate v9 → compatibility read/write → проверка каждого инварианта → явная резервная копия → активация. До этого момента текущими источниками данных остаются `SoulChat` и `SoulScene`.
