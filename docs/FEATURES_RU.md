# Возможности SoulExe

## 1. Ролевые диалоги

Обычный чат связывает одного персонажа с отдельной историей диалога. У персонажа может быть несколько самостоятельных чатов с собственными названием, временем обновления, памятью и краткой сводкой. Это удобно, когда один и тот же персонаж участвует в разных сюжетах или требуется сохранить отдельные варианты развития истории.

В ленте сообщения показываются с разделителями дат. Пользователь может искать историю, создавать и переименовывать чаты, закреплять важные диалоги, удалять ненужные и использовать действие **«Продолжить»** для следующей реплики персонажа без обычного текста пользователя.

### Ролевая разметка

SoulExe умеет визуально выделять несколько типов текста, даже когда модель выдала их одной строкой.

| Тип | Пример | Как отображается |
|---|---|---|
| Действие | `*Надя улыбается*` | Отдельный акцентный стиль действия. |
| Мысли | `<think>Она сомневается</think>` | Отдельный стиль размышления; его можно скрыть. |
| Речь | `«Доброе утро»` | Стиль речи, настраиваемый в оформлении. |

Переключатели скрытия маркеров удаляют только визуальный шум в интерфейсе. Исходный текст сообщения и контекст для модели не меняются от этих настроек.

## 2. Персонажи, лор и персоны пользователя

Карточка персонажа содержит имя, портрет, описание, характер, сценарий и системные правила. Для поддержания мира можно подключать лорбуки — наборы постоянных сведений о местах, событиях, предметах и правилах. Карточки поддерживают импорт и экспорт, а также локальные аватары.

**Персона пользователя** — это отдельный переиспользуемый профиль того, кем пользователь является в истории. В нём удобно хранить имя, возраст, роль, внешность, способности, биографию и постоянные факты. Персона не заменяет карточку персонажа: она дополняет контекст выбранного ИИ-персонажа образом собеседника.

## 3. Память и сводки

Длинный ролевой диалог нельзя бесконечно передавать модели целиком. SoulExe использует несколько уровней контекста:

| Слой | Назначение |
|---|---|
| Свежие сообщения | Сохраняют текущую манеру разговора и ближайшие детали. |
| Краткая сводка | Сжимает ход истории в короткое описание. |
| Soul Memory | Хранит устойчивые факты: состояния, инвентарь, отношения, события и лор. |
| Лор и персона | Добавляют заранее заданные правила мира и роль пользователя. |

Обслуживание памяти планируется в фоновом режиме после фактической паузы в чтении. Поэтому основной ответ не должен ждать завершения дополнительных задач памяти. Однако время работы всё равно зависит от производительности ПК и выбранной модели.

## 4. Сцены

Сцена — это общий диалог двух персонажей под заданными рамками. Пользователь задаёт участников, сценарий, место, время, настроение, цель, отношения и правила. Сцена работает в двух режимах:

| Режим | Поведение |
|---|---|
| **Ручной** | Следующая реплика запускается вручную кнопкой со стрелкой вверх. |
| **По очереди** | Программа поддерживает автоматические ходы через заданную задержку. |

Режиссёрское событие вводится отдельно от обычной реплики. Оно описывает факт, изменение среды или указание сюжету и отображается по центру ленты. В шапке сцены показывается состояние и обратный отсчёт до следующего автоматического хода, когда сервер назначил его время.

## 5. Mobile-клиент

SoulExe Mobile не создаёт отдельную облачную копию данных. Он использует локальный API Windows-клиента и работает с теми же персонажами, чатами, сценами и аватарами.

| Функция | Что доступно на телефоне |
|---|---|
| Подключение | Поиск SoulExe в Wi‑Fi, ручной LAN-адрес, вход по логину и паролю. |
| Чаты и сцены | Общий список, история, ввод сообщений, сцены с паузой, режиссёрским событием и следующей репликой. |
| Синхронизация | Тихое обновление списков и активной ленты без обязательного перезапуска Windows-клиента. |
| Персонажи | Просмотр, редактирование, создание, генерация и загрузка фото-аватаров на ПК. |
| Интерфейс | Портретная мобильная компоновка, безопасные отступы, поддержка высокой Android-клавиатуры, демо-режим без сервера. |

## 6. Модель и параметры генерации

SoulExe рассчитан на локальный запуск GGUF-моделей через `llama-server`. В параметрах доступны настройки контекста, лимита ответа, температуры и расширенного семплирования. Параметр **«Бюджет рассуждений»** передаёт лимит скрытых токенов размышлений только моделям и рантаймам, которые поддерживают reasoning.

Большее значение бюджета рассуждений не гарантирует лучший результат: оно может повысить время ожидания и нагрузку. Для ролевого чата обычно важнее подобрать подходящую модель, размер контекста и разумный лимит генерации.
