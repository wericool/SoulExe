# SoulExe — редизайн, вторая волна

> Рабочая дорожная карта после первоначального прохода «Иммерсивный театр».
> Цель: убрать ощущение склейки новой театральной оболочки и legacy-экранов,
> не меняя прикладную логику, persistence, команды, bindings и безопасные
> ограничения WPF из `WPF_UI_RULES.md`.

## Правила работы

- [ ] Перед началом каждого этапа прочитать `WPF_UI_RULES.md` и связанные XAML.
- [ ] Менять один экран или компонент за шаг.
- [ ] Не создавать global implicit templates для layout-critical controls.
- [ ] Сохранять существующие `Binding`, `Command`, `x:Name` и code-behind обработчики.
- [ ] После этапа: `dotnet build SoulExe.csproj -warnaserror`.
- [ ] После этапа: `dotnet run --project SoulExe.ConversationChecks\SoulExe.ConversationChecks.csproj`.
- [ ] После этапа: собрать EXE и вручную проверить RU и EN.
- [ ] После подтверждения: обновить этот файл, сделать отдельный commit и push.
