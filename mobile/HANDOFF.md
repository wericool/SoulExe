# SoulExe — Handoff для следующей нейросети

## Цель проекта

SoulExe — мобильное Expo-приложение в формате narrative chat. Текущая версия реализует дизайн и локальные mock-сценарии по архиву `NewStyleMobile.zip` и документу `MOBILE_APP_DESIGN_BRIEF.md`. Реальные данные, backend-синхронизация и подключение к SoulExe Desktop пока намеренно не подключены.

## Технологический стек

Проект находится в `/home/ubuntu/soulexe-mobile`. Используются Expo SDK 54, React Native, Expo Router, TypeScript, NativeWind и локальные mock-состояния. Главный экран и почти весь текущий UI находятся в `app/(tabs)/index.tsx`. Дизайн-решения описаны в `design.md`, история задач — в `todo.md`.

Команды для работы:

```bash
pnpm install
pnpm dev
pnpm check
pnpm lint
pnpm test
```

Не нужно добавлять API-ключи, серверную синхронизацию, базу данных или реальные сетевые запросы, пока это отдельно не согласовано.

## Уже реализовано

Приложение содержит onboarding с поиском SoulExe по Wi‑Fi, выбором найденного компьютера и demo-режимом. Реализованы разделы «Разговоры», «Библиотека» и «Ещё». В библиотеке есть переключение между «Персонажи» и «Персоны», создание и редактирование сущностей, а также детальные профили.

В «Разговорах» есть личные и групповые mock-чаты. Новый чат создаётся через выбор «Личный разговор» или «Групповой разговор». Для группового разговора при создании выбираются ровно два персонажа. После создания участники фиксированы: их нельзя удалять, заменять или добавлять. При этом остальные параметры групповой истории можно менять: название, сценарий, место, настроение, цель, задержку, «Соблюдать сценарий» и «Развивать сюжет».

В групповой карточке разговора отображаются два мини-аватара, подпись «Групповой разговор · 2 персонажа», место и настроение. Название можно локально редактировать из карточки. В раскрытом group header показаны два read-only участника, preview параметров истории и кнопка редактирования параметров.

## Правила отображения сообщений

Это критически важная часть дизайна, её нельзя менять без согласования:

| Контекст | Роль | Позиция | Оформление |
|---|---|---|---|
| Личный чат | AI-персонаж | Слева | Обычное облачко персонажа |
| Личный чат | «Вы» | Справа | Облачко пользователя |
| Личный чат | Выбранная пользовательская персона | Справа | Облачко пользователя/персоны |
| Групповой чат | Первый персонаж | Слева | Облачко с первым цветовым акцентом |
| Групповой чат | Второй персонаж | Справа | Облачко со вторым цветовым акцентом |
| Групповой чат | «Вы» или выбранная персона | По центру | Облачко |
| Любой чат | Режиссёр | По центру | Без облачка, без имени и без подписи; это текст о происходящем внутри мира |

В composer слева находится раскрывающаяся кнопка «Персона» со списком «Вы» и созданных персон. Справа находится только существующая icon-only кнопка Режиссёра; не добавлять рядом текст «Режиссёр» и не дублировать иконку.

## Ограничения продукта

Состав группового разговора задаётся один раз при создании и затем неизменяем. Нельзя показывать действия удаления, замены или добавления участников. Параметры истории, наоборот, редактируемы. Параметра «Отношения участников» в продукте нет — не добавлять его в формы, preview или профили.

Режиссёр не является отдельным говорящим персонажем. Его сообщения — нейтральные описания событий внутри мира. Не использовать для них имя, avatar, outline, отдельный bubble или label.

## Что сделать дальше

Рекомендуемый порядок:

1. Проверить на мобильном portrait-экране личный чат: AI-персонаж слева, «Вы» и выбранная персона справа.
2. Проверить групповой чат: первый персонаж слева, второй справа, «Вы» и персона по центру в облачке, Режиссёр по центру без облачка.
3. Добавить отдельные аватары пользователя и выбранной пользовательской персоны в личной ленте, если это не нарушит композицию.
4. Добавить read-only preview типа разговора в шапку личного и группового чата.
5. Добавить preview сценария и цели в карточку разговора, не добавляя отношений участников.
6. Добавить состояния непрочитанных сообщений и последнего автора в списке разговоров.
7. Продолжать только визуальную работу на mock-данных до отдельного разрешения на реальные данные и синхронизацию.
